# Текущее состояние проекта

> Это снимок исходного кода, а не подтверждение состояния опубликованного сайта. Работающий production-адрес и процесс публикации в репозитории однозначно не описаны.

## Что уже реализовано

- Публичный сайт филиала школы на React: главная страница, страницы о школе и направлениях обучения, приём, общественная жизнь, новости и контакты. Список маршрутов находится в [`src/App.jsx`](./src/App.jsx).
- Адаптивная навигация, общие шапка и подвал, визуальные секции главной страницы и отдельные страницы контента.
- Express API для новостей и выпусков газеты, сотрудников, слайдов, галереи, клубов, событий, статистики и обращений. Серверный код — [`server/index.js`](./server/index.js).
- Административный интерфейс для редактирования содержимого и просмотра обращений. Данные API хранятся в [`server/data.json`](./server/data.json), а не в PostgreSQL.
- Vite development server с проксированием `/api` на Express; production-сборка фронтенда выполняется командой `npm run build`.

## Проверки и инструменты

- Скрипты пакета: `npm run dev`, `npm run build`, `npm start`, `npm run server`, `npm run client`.
- В `package.json` не определены отдельные команды тестирования или линтинга.
- `npm run build` успешно выполнена после подготовки документации. Vite сообщил о размере JavaScript-бандла более 500 kB; сборка завершилась, но предупреждение можно учесть при отдельной работе над производительностью.
- Результат production-сборки нужно сверять с текущей версией репозитория; прежнее наличие папки `dist/` само по себе не доказывает, что сборка актуальна.

## Что проверить перед дальнейшей разработкой

1. **Безопасность доступа и данных.** В исходниках и локальном JSON-файле есть детали, связанные с учётной записью и аутентификацией. Не переносить их в промпты, логи и документацию; перед публикацией проверить и заменить тестовые/встроенные значения, а также сменить доступы. Не публиковать `server/data.json`.
2. **Запуск в Docker.** [`docker-compose.yml`](./docker-compose.yml) запускает Django-команды и PostgreSQL, тогда как в проекте нет Django-точки входа, а сервер использует JSON-файл. Кроме того, [`Dockerfile`](./Dockerfile) заявляет порт, который не совпадает с портом Express по умолчанию. Не считать контейнерный сценарий рабочим без отдельной проверки.
3. **Навигация по страницам.** Некоторые маршруты перенаправляют на другие разделы, хотя соответствующие файлы страниц присутствуют. Например, файлы страницы галереи и событий не означают, что эти страницы подключены в маршрутизаторе.
4. **Административная оболочка.** В [`src/App.jsx`](./src/App.jsx) условие скрытия общей шапки/подвала проверяет префикс, отличный от фактического маршрута `/admin`; проверить ожидаемое поведение панели.
5. **Актуальность текстов.** [`README.md`](./README.md) содержит описание функций и входа, которое может расходиться с работающим кодом и сохранённым состоянием. Перед использованием сверять его с реализацией и не полагаться на опубликованные там учётные данные.

## Рекомендуемый следующий шаг

Сначала подтвердить требуемый способ публикации и реальные данные доступа; затем проверить production-сборку и отдельно решить, какие перенаправленные разделы должны стать полноценными страницами. См. также [`Development-Guide.md`](./Development-Guide.md) и [`AI-Onboarding.md`](./AI-Onboarding.md).
